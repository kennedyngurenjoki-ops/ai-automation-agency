# Commercial plan — a hypothesis to validate

## Single project selected

[ai-automation-agency](https://github.com/kennedyngurenjoki-ops/ai-automation-agency) is the best
near-term service-income candidate from the source reviewed, not a proven highest-return investment.
It already had a customer-facing landing/form foundation. The missing build consistency and actual
intake storage were a smaller, testable gap than completing a broad chatbot or e-commerce platform.

The review inventoried 26 owned repositories: 17 non-forks and 9 forks. Trees were inspected for
15 non-empty originals, and key source/setup files for the four strongest substantive candidates.
Many projects were documentation-only; repository descriptions and claimed dollar values were not
accepted as proof of working features, customers or revenue. See [assessment](PROJECT_ASSESSMENT.md).

## First buyer and offer

Target one small professional-services business that manually copies website enquiries into a
spreadsheet or work queue. This is a buyer hypothesis, not a verified market segment.

Offer **one intake/handoff pilot**: required-field validation, reviewed consent/privacy information,
durable capture, a confirmation receipt, private operator review/export and a clear response process.
Use an isolated client instance with explicit ownership and hosting responsibilities. The existing
code is the reusable starter, not an already-integrated CRM, WhatsApp bot or automatic outreach agent.

Agree written scope, exclusions, cost and acceptance checks before work starts. Demonstrate with
synthetic data: a valid request is saved once, invalid/withheld-consent requests are rejected, retries
are safe, the operator can retrieve it and it survives a restart. Handover must include source,
setup, data ownership, backups and a defined support boundary.

## Pricing to test — not a market quote

A possible discussion range is **US$250–$750 one-time setup**, with **US$50–$150/month optional
maintenance** only where there is real ongoing work. These are unvalidated experiments, not expected
sales or established market rates. Choose currency and quote only after discovery and owner approval.
Disclose hosting, domains, taxes and third-party subscriptions separately.

Revenue is not profit: account for implementation hours, support, acquisition and costs you bear.
Recovered staff capacity is not automatically cash savings. No guaranteed income or customer-results
claims are made by this code or plan.

## Validate before expanding

1. Choose one reachable niche and have five genuine discovery conversations about the current process.
2. Ask about actual enquiry volume, missing information, manual steps and who can approve a purchase.
3. Demonstrate the working intake flow and distinguish it from proposed integrations.
4. Seek one paid pilot with written acceptance criteria before adding speculative SaaS features or paid ads.
5. Measure delivery hours, support effort, handoff errors and willingness to pay; revise if uneconomic.
6. Publish case studies only from real, permissioned outcomes. Never invent clients or savings percentages.

No prospect has been contacted or charged by this work. Outreach, public pricing, live integrations
and deployment remain separate owner-approved actions.
